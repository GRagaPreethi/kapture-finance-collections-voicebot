# 7. verify_customer

Purpose:

Authenticate the customer before debt disclosure.

Input:

{
"account_id": "ACC-88392",
"verification_code": "1234"
}

Success:

{
"verified": true,
"customer_name": "Rahul Sharma",
"message": "Identity verified successfully."
}

Failure:

{
"verified": false,
"message": "Verification failed."
}

The backend must be authoritative.

The LLM must NOT manually assume authentication succeeded.

After failed verification:

* remain AUTH_PENDING
* do not disclose debt
* allow a reasonable retry
* eventually log VERIFICATION_FAILED and end/escalate

Never log the raw verification code.
